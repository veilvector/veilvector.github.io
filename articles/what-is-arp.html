ARP: Finding Devices on a Local Network

Your computer knows the IP address it wants to reach. But how does it find the right device on the local network? ARP helps it connect the address it knows to the hardware address it needs.

Networking fundamentals · Guide 019
01 — The missing clue

Your computer knows where. But does it know who?

Imagine your laptop wants to send data to your phone. The phone is connected to the same local network, and your laptop knows its IPv4 address: 192.168.1.20.

There is just one missing piece. To deliver a frame across the local network, the laptop needs the destination's MAC address.

An IP address and a MAC address serve different purposes. An IP address helps identify a device's location at the network layer. A MAC address identifies a network interface on the local link.

How does the laptop connect the two? For IPv4, one answer is ARP.

02 — Meet ARP

The network asks a question

ARP stands for Address Resolution Protocol. On an IPv4 local network, it helps a device discover which MAC address corresponds to a known IPv4 address.

Picture your laptop asking everyone on the local network: “Who has 192.168.1.20? Please tell me your MAC address.”

LOCAL NETWORK / ARP REQUEST
FROM: LAPTOP
Who has 192.168.1.20?
I need the MAC address associated with this IPv4 address so I can deliver data on the local network.
↗ ARP request broadcast

An ARP request is broadcast on the local network. Devices receive it, but the device that owns the requested IPv4 address is the one expected to respond with its mapping.

03 — The reply

The right device answers

Suppose the phone owns the address 192.168.1.20. It recognizes the address in the request and replies with its MAC address.

Laptop
→
Who has 192.168.1.20?
Phone
→
Here is my MAC address

The laptop can now associate the IPv4 address with the MAC address returned in the reply. It uses that information to address frames to the phone on the local network.

The example below uses a fictional MAC address to show what the mapping might look like.

DISCOVERED ADDRESS MAPPING
IPv4 address
192.168.1.20
MAC address
3C:52:82:7A:91:4F

ARP resolves an address on the local link. If the destination is outside the local subnet, your computer typically resolves the MAC address of its next-hop router instead of the remote host's MAC.

04 — Remembering the answer

It doesn't have to ask every time

If your laptop had to broadcast an ARP request for every packet, it would create unnecessary network traffic.

Instead, devices keep recently learned address mappings in an ARP cache. When the laptop needs to communicate with the same local device again, it can often reuse the cached mapping until it expires or is replaced.

ARP CACHE / EXAMPLE ENTRIES
192.168.1.20
3C:52:82:7A:91:4F
192.168.1.1
84:16:F9:2B:44:08

In this example, the first entry represents another device on the local network. The second could represent the local router. Actual entries depend on the network and the devices communicating.

The important idea is simple: ARP discovers a mapping, and the cache can remember it temporarily.

05 — The security connection

What if the answer is a lie?

ARP is a normal part of IPv4 networking. But classic ARP does not provide strong authentication for its replies. In some network environments, a malicious device can send forged ARP messages that associate an IP address with the wrong MAC address.

This technique is known as ARP spoofing or ARP poisoning. Depending on the network and the attacker's position, it can redirect local traffic, interrupt communication, or help an attacker attempt a man-in-the-middle attack.

The security lesson: if a system trusts an address mapping, manipulating that mapping can affect where traffic goes. Defenders can reduce risk with appropriate network segmentation, monitoring, and protections such as Dynamic ARP Inspection where supported and correctly configured.

You don't need to study the attack in depth yet. Just remember that ordinary network protocols can create security risks when their assumptions are abused.

06 — One useful distinction

ARP is for IPv4

ARP is used to resolve IPv4 addresses to link-layer addresses on local networks. IPv6 does not use ARP; it uses Neighbor Discovery Protocol (NDP), which is part of IPv6's Internet Control Message Protocol (ICMPv6).

For now, keep this simple distinction in mind: ARP belongs to IPv4, while IPv6 uses NDP for neighbor discovery.

07 — Connect the clues

From an IP address to local delivery

Local frame delivery

ARP helps a device find the MAC address associated with a known IPv4 address on the local network. The device can then use that mapping to send frames to the appropriate local destination.

One detail matters: when you're communicating with a server beyond your local subnet, your computer generally sends the frame to its next-hop router. It doesn't use ARP to discover the remote server's MAC address across the internet.

08 — Check your understanding
PAUSE FOR A SECOND

THE TAKEAWAY

ARP connects IPv4 addresses to MAC addresses on a local network. It uses requests and replies to discover mappings, while the ARP cache helps devices reuse recently learned information. Because forged ARP messages can mislead devices, ARP is also worth understanding from a security perspective.
