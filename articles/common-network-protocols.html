Common Network Protocols

Devices don't just send data randomly. They follow agreed rules that tell them how communication should happen. Let's explore the protocols working behind the scenes whenever you use a network.

GUIDE 024 · NETWORKING
01 / THE QUESTION

How do computers understand each other?

You open a website.

Your device finds the destination, sends traffic through the network, and eventually receives a response.

It feels like one simple action. Underneath it, several processes work together to make that communication possible.

Here's the question hiding underneath all of this: How do different systems agree on what their communication means?

They use protocols.

DIFFERENT RULES · ONE NETWORK
DNS Find a name's address
→
TCP / UDP Move data between applications
→
HTTP / HTTPS Exchange web requests and responses

These protocols have different responsibilities. Together with other network protocols, they help communication work from one step to the next.

02 / THE BASICS

What is a protocol?

A network protocol is a set of agreed rules that defines how devices communicate.

Think about two people having a conversation. They need a shared language and some understanding of how the conversation works. Without that shared understanding, messages can be misunderstood.

Computers need something similar.

A protocol can define how a message is structured, how it is sent, how it is received, and what the receiver should do with it.

Keep this distinction in mind.

A protocol isn't a device or an application. It's a set of rules that helps systems communicate in an agreed way.

03 / FOLLOW THE REQUEST

One request, many protocols

Let's go back to something familiar: visiting a website.

You enter a domain name into your browser. Your device may need to resolve that name, establish or reuse a connection, protect the exchange, and request the page.

This is a simplified view, not a fixed sequence for every visit. Cached DNS answers, reused connections, and different HTTP versions can change the steps.

These protocols aren't competing with each other. They operate at different parts of the communication process, each with its own responsibility.

04 / MEET THE PROTOCOLS

Protocols you'll meet everywhere

You don't need to memorize a huge table before continuing. The more useful skill is recognizing what each protocol is trying to do.

DNS
Name resolution

Helps find records associated with domain names, including IP addresses. For example, it can help a browser find the address for a website.

DHCP
Network configuration

Automatically supplies settings such as an IP address, subnet mask, default gateway, and DNS server to a device.

ARP
Local IPv4 address resolution

Helps a device discover the MAC address associated with an IPv4 address on its local network. IPv6 uses Neighbor Discovery instead of ARP.

TCP
Reliable, ordered transport

Provides a connection-oriented stream of data with mechanisms for reliable, ordered delivery.

UDP
Lightweight transport

Sends datagrams without TCP's built-in delivery and ordering guarantees. It can be useful when low overhead or application- controlled delivery behavior matters.

HTTP
Web communication

Defines how web clients and servers exchange requests and responses. HTTP by itself does not provide transport encryption.

HTTPS
Protected web communication

HTTP protected by TLS in common deployments, providing encryption and server authentication when correctly configured and validated.

Why this matters in cybersecurity

Protocol knowledge helps you interpret network traffic. DNS activity relates to name resolution, while HTTP logs may show which web paths a client requested. Unusual activity deserves context and investigation; one request alone doesn't prove an attack.

05 / THINK LIKE AN INVESTIGATOR

What would you look for?

Imagine you're reviewing network activity for a college website. One device makes repeated DNS queries and then sends requests to several web paths.

Rather than treating every event as a separate mystery, start by asking what each part of the activity tells you.

  1. Which names were queried?

    Check the domains, response addresses, frequency, and whether the activity fits the device's normal behavior.

  2. Which web paths were requested?

    Review the paths, response codes, timestamps, and whether the requests succeeded or failed.

  3. Do the events connect?

    Compare source device, destination, timing, and other logs to build a timeline before drawing a conclusion.

The useful habit is simple: identify the protocol, understand its role, and investigate whether the activity makes sense in context.

06 / THE BIGGER PICTURE

From protocols to services

Protocols help devices exchange information, but that communication often exists to reach a service running on a system.

THE NETWORKING PICTURE
Device

Uses its network settings and IP address.

→
Network

Moves traffic locally or through a router.

→
Service

Receives and responds to the relevant traffic.

Routing, address translation, and other network functions may be involved along the way, depending on the environment.

A server might provide a website. Another might offer remote access, DNS, or email. Each service has its own purpose and may use particular protocols and ports.

That leads to the next question: What exactly is a network service, and how can we discover it?

TAKEAWAY · 024

Network protocols are agreed rules that allow systems to communicate. DNS helps with name resolution, DHCP provides network configuration, ARP helps resolve local IPv4 addresses to MAC addresses, TCP and UDP handle transport, and HTTP/HTTPS support web communication. Understanding these roles is a useful first step toward reading and investigating network traffic.
