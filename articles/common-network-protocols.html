Common Network Protocols

Devices don't just send data randomly. They follow agreed rules that tell them how communication should happen. Let's explore the protocols working behind the scenes whenever you use a network.

GUIDE 024 · NETWORKING
01 / THE QUESTION

How do computers understand each other?

You open a website.

Your device finds the destination, sends traffic through the network, and eventually receives a response.

It feels like one simple action. But underneath it, several processes are working together.

Here's the question hiding underneath all of this: How do two completely different systems agree on what their communication means?

They use protocols.

02 / THE BASICS

What is a protocol?

A network protocol is a set of agreed rules that defines how devices communicate.

Think about two people having a conversation. They need a shared language and some understanding of how the conversation works. Without that shared understanding, messages can be misunderstood.

Computers need something similar.

A protocol can define how a message is structured, how it is sent, how it is received, and what the receiver should do with it.

A protocol is not a device or an application. It is a set of rules that helps systems communicate in an agreed way.

04 / MEET THE PROTOCOLS

Protocols you'll meet everywhere

You don't need to memorize a huge protocol table before continuing. The more useful skill is recognizing what a protocol is trying to do.

THE JOB BEHIND THE NAME
DNS
Name resolution

Helps translate domain names, such as example.com, into IP addresses.

DHCP
Network configuration

Automatically provides devices with network settings such as an IP address, subnet mask, gateway, and DNS server.

ARP
Local address resolution

Helps IPv4 devices discover the MAC address associated with a local IPv4 address.

TCP
Reliable transport

Establishes a connection and provides mechanisms for reliable, ordered delivery of data.

UDP
Lightweight transport

Sends data without TCP's connection and reliability mechanisms. It can be useful when low overhead matters.

HTTP
Web communication

Defines how web clients and servers exchange requests and responses.

HTTPS
Protected web communication

Uses HTTP over a protected connection, typically with TLS, to provide encryption and server authentication.

Why this matters in cybersecurity

Understanding protocol roles helps you interpret network traffic. For example, DNS activity relates to name resolution, while HTTP requests can reveal which web paths a client tried to access. Context matters: unusual traffic is worth investigating, but one protocol or request alone does not automatically prove an attack.

TAKEAWAY · 024

Network protocols are agreed rules that allow systems to communicate. DNS helps with name resolution, DHCP provides network configuration, ARP helps resolve local IPv4 addresses to MAC addresses, TCP and UDP handle transport, and HTTP/HTTPS support web communication. Understanding these roles is a useful first step toward reading and investigating network traffic.
