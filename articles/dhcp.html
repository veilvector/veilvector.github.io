DHCP: How Devices Get an IP

You join a Wi-Fi network, open a browser, and somehow your device already knows where it belongs. Who gave it that information?

Guide 020 · Network fundamentals
01 — Joining the network

You connected. But who gave you an address?

You connect your laptop to Wi-Fi.

You didn't manually type an IP address. You didn't choose a subnet or enter the address of a gateway. You simply selected the network, connected, and started browsing.

Yet your device has the network information it needs to communicate with other devices and reach the internet.

Something provided that configuration automatically. One of the main services responsible is DHCP — Dynamic Host Configuration Protocol.

02 — The job

DHCP handles the setup

DHCP automatically provides devices with network configuration when they join a network.

Depending on the network, that configuration can include several important pieces of information.

A few things DHCP can provide
IP address

Identifies the device's network-layer address.

Subnet mask

Helps determine which addresses belong to the local subnet.

Default gateway

Provides a route to destinations outside the local network.

DNS server

Identifies a resolver the device can use for name lookups.

In many home networks, the router also performs the DHCP server role. In larger networks, DHCP may be provided by a separate server or network service.

03 — The conversation

Meet DORA: DHCP's four-step process

When a device needs an IPv4 address, a common DHCP exchange follows four steps. They are easy to remember using the name DORA.

DORA · DHCPv4
01 Discover

The client searches for a DHCP server.

→
02 Offer

A server proposes an address and settings.

03 Request

The client requests the offered configuration.

→
04 Acknowledgement

The server confirms the assignment.

  1. Discover

    The device broadcasts a DHCP discovery message to find an available DHCP server. At this point, it may not yet have a usable IPv4 address for normal network communication.

  2. Offer

    A DHCP server responds with an offer. It proposes an available IP address and can include other network settings.

  3. Request

    The device sends a request indicating that it wants to use the offered configuration.

  4. Acknowledgement

    The server sends an acknowledgement, commonly called DHCPACK, confirming the assignment. The device can then configure its network interface with the information received.

That's the basic exchange: the device asks, the server offers, the device requests, and the server confirms.

04 — Follow the messages

These messages can also appear in packet captures. Tools such as Wireshark can help you examine DHCP traffic and follow the exchange between a client and a server.

05 — Not forever

An IP address is often leased

A DHCP address is commonly assigned as a lease. This means the device is allowed to use the assigned configuration for a particular period.

Before the lease expires, the device can communicate with the DHCP server to renew it. If the device disconnects or the lease eventually expires, the address may later become available for another device.

This makes address management easier when laptops, phones, and other devices regularly join, leave, or move around a network.

06 — The bigger picture

What if hundreds of devices join?

Imagine a college network with hundreds of laptops and phones. Every day, students arrive, connect to Wi-Fi, move between buildings, and leave again.

If an administrator had to configure every device manually, keep track of every address, and avoid assigning the same address to two devices at once, managing the network would quickly become difficult.

DHCP automates much of that work. Instead of manually configuring every device, the network can provide the required settings through the DHCP service.

The result is simpler network administration and more consistent address management.

07 — The security clue

Why does DHCP matter in cybersecurity?

DHCP is more than a convenience. Its records can help defenders understand which device was assigned an address and when that assignment occurred.

Imagine an investigation where a suspicious activity log contains the IP address 192.168.1.24. You want to determine which device was using that address at the time of the event.

A DHCP lease record may help connect the IP address with a client identifier or MAC address and a lease period. The exact information available depends on the network's configuration and logging.

An IP address alone may not identify a device reliably. Addresses can change, and an address can be assigned to different devices at different times. Investigators need to consider timestamps and other supporting evidence.

This is why defenders correlate network events with other clues rather than relying on a single IP address. DHCP records can provide useful context, but they do not prove by themselves that a device or user performed a particular action.

08 — Connect the clues

DHCP and ARP have different jobs

DHCP and ARP both help devices participate in an IPv4 network, but they solve different problems.

DHCP

Helps a device obtain network configuration, commonly including an IP address.

ARP

Helps resolve a local IPv4 address to a link-layer address on the same network segment.

Think of DHCP as helping a device get its network settings, while ARP helps it find the local destination address needed to deliver certain IPv4 packets over the local link.

09 — Check your understanding

One question before you move on

PAUSE FOR A SECOND

You connect your laptop to a new Wi-Fi network and it automatically receives an IP address. Which service most likely provided the network configuration?

The answer is DHCP. In many networks, a DHCP server provides an address and other configuration information without requiring you to enter everything manually.

THE TAKEAWAY

DHCP automatically provides devices with network configuration, commonly including an IP address, subnet mask, default gateway, and DNS information. Its familiar four-step DHCPv4 exchange is DORA: Discover, Offer, Request, and Acknowledgement. DHCP leases and logs can also help administrators manage addresses and investigate network activity.
