BEGINNER PATH GUIDE 015

How Cyber Attacks Actually Happen

Cyber attacks rarely begin with the dramatic moment people imagine. Usually, they begin with something much smaller — a message, a mistake, an exposed service, a stolen password, or a weakness someone discovers.

01 / THE BIG QUESTION

So how does an attack actually unfold?

Imagine a company notices something unusual on one of its computers. A new account appeared. A strange process is running. And the machine has started communicating with an unfamiliar server.

The important question isn't simply: “Was the system attacked?” The better question is: “What happened, step by step?”

A simplified attack journey
01 / ENTRY Initial access Finding a way in
→
02 / ACTION Execution Making something run
→
03 / STAY Persistence Trying to maintain access
→
04 / LEARN Discovery Exploring the environment
→
05 / RESULT Impact Attempting to reach an objective

This is a simplified example, not a fixed recipe. Real attacks may skip stages, repeat them, or follow a different order.

02 / INITIAL ACCESS

First, someone finds a way in.

An employee receives an email that appears to come from a familiar service.

The message contains a link asking them to sign in. They click it and enter their credentials.

If the page is controlled by an attacker, those credentials may now be exposed — potentially giving the attacker a route into the environment.

This is called initial access — the point where an attacker first gains a foothold in a target environment.

Phishing is one possible route, but not the only one. Stolen credentials, exposed services, vulnerable software, malicious files, and compromised accounts can also provide entry.

One possible entry path
01 Fake email
→
02 Link opened
→
03 Credentials exposed
→
04 Possible account access
03 / EXECUTION

Getting access isn't the same as getting something done.

Access alone may not accomplish the attacker's objective. They may need a command, script, malicious program, or another action to run. This is where execution becomes important.

From a defender's perspective, this can leave useful clues: processes starting unexpectedly, unusual commands, scripts running at strange times, or applications behaving differently.

INVESTIGATOR'S QUESTION

A new process suddenly appears on a workstation. What would you want to know?

  • What process started?
  • Which user started it?
  • What launched it?
  • When did it start?
  • What did it communicate with?

One process name rarely tells the whole story. Its parent process, command line, user, timing, and network activity can help explain whether it belongs to normal work or deserves closer investigation.

04 / PERSISTENCE

What if the attacker wants to stay?

An attacker may not want to lose access when a computer restarts or a session ends. They may attempt to maintain access through an account, service, scheduled task, or another mechanism.

This is broadly known as persistence.

IMPORTANT DISTINCTION

Unusual doesn't automatically mean malicious.

Legitimate software also creates services, scheduled tasks, and startup entries. A defender needs to examine who created an item, when it appeared, what it runs, and whether it makes sense for that system.

05 / DISCOVERY

Now the environment becomes the target of curiosity.

Once inside, an attacker may need to understand the environment. What systems exist? Which accounts are available? What information is stored here? What other machines can be reached?

This stage is called discovery: learning about the systems, users, software, and resources around them.

CLUE 01 / IDENTITY

Users

Which accounts exist, and which account is currently in use?

CLUE 02 / SYSTEM

Processes

What software is running on the system?

CLUE 03 / NETWORK

Connections

Which systems or services is the machine communicating with?

CLUE 04 / DATA

Files

What information and resources are available?

06 / IMPACT

Eventually, the activity may reach an objective.

The objective depends on the attacker and the environment. It could involve stealing information, disrupting services, encrypting files, changing data, or abusing an account.

This is where the earlier concepts from the Beginner Path start connecting together.

Connecting the clues
ACCESS Stolen account
→
SYSTEM Unexpected process
→
NETWORK Unfamiliar connection
→
DATA Information accessed

This is an illustrative sequence, not proof of an attack. Each event needs context, and the relationship between events matters.

07 / REAL INCIDENTS

But attacks aren't always this simple.

Real incidents can involve multiple systems, accounts, techniques, and stages. An attacker might enter through phishing, move to another system, discover additional accounts, obtain higher privileges, access sensitive information, and attempt to hide their activity.

The exact sequence can vary. Defenders don't simply memorize one attack pattern. They investigate the evidence left behind by activity.

THE DEFENDER'S VIEW

Imagine these events appear during an investigation.

EVENT 01
Suspicious email

A user receives a message that may be phishing.

EVENT 02
Unexpected login

An account signs in at an unusual time or from an unfamiliar source.

EVENT 03
New process

A process appears that needs further investigation.

EVENT 04
Network connection

The machine contacts an unfamiliar IP address.

EVENT 05
File activity

Files are accessed shortly afterwards.

Each event alone may have a legitimate explanation. Together, they form a timeline worth investigating.

08 / CONNECTING THE CLUES

This is where cybersecurity becomes investigation.

Remember the clues you've collected throughout this path. Each concept helps answer a different question about the same incident.

01 / NETWORKING

IP address + port

Where is the system communicating, and which service is involved?

02 / DNS

Domain → IP

What destination is a system trying to reach?

03 / SYSTEM ACTIVITY

Process + behaviour

What changed on the system?

04 / IDENTITY

Authentication + authorization

Who accessed the system, and what were they allowed to do?

And then there are the security goals: confidentiality, integrity, and availability. An incident can affect one, two, or all three.

The more pieces you understand, the easier it becomes to see the bigger picture.

The bigger picture
ENTRY Phishing, vulnerability, or credentials
→
ACTIVITY Processes, accounts, and network
→
DISCOVERY Systems, users, and data
→
IMPACT Data, systems, or services
09 / THE LESSON

A cyber attack is rarely one magical action.

It is a sequence of actions and events. Attackers try to move from one step to another. Defenders try to detect, understand, interrupt, and contain those steps.

And every step can leave clues.

TAKEAWAY / BEGINNER PATH COMPLETE

Cyber attacks can involve initial access, execution, persistence, discovery, and impact. The exact path varies, but understanding the sequence helps defenders turn individual events into a meaningful investigation.
